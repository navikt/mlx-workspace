### What changed today, and what caught what

- The workspace guard refuses to measure if the agent's working directory holds
  anything we did not put there. Written after a committed solution tree was
  found in the default model's workspace, five days old.
- `touches` is declared per task in tasks.json. The regex that guessed it made
  G2 impossible to pass, and three green builds were scored as failures.
- A retired task no longer scores as a failure on timeout. It was moving the
  denominator against whichever model is slower.
- `bench/ops.py` groups runs by harness generation and refuses to test across
  them. It caught a pooled run of mine an hour before the review caught the
  rest.

### Still open from the review, none of it blocking the rerun

- `assert_serving_profile` cannot fail while both models are in the HF cache,
  because /v1/models lists the cache rather than what is loaded.
- The sandbox grants gradle but not a JDK the project can use, and
  agents-prompt.md tells the model to run `mise run`, which the sandbox blocks.
  Both cost the slower model minutes against a 420 second cap.
- Four of eleven tasks are never scored and three fail for both arms, so the
  comparison rests on three tasks. That is the design problem under all of this:
  at this sample size a one-task difference needs roughly 15 runs an arm to
  detect.
