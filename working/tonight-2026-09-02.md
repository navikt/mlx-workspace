## Found by the research pass — act on these before more runs

- [x] **Published p-value was wrong.** We printed p = 0,008; the two-sided floor at four runs
      against five is 2/126 = 0,016. The enumeration counted the same extreme arrangement in
      both tails. Corrected in `MODELS.md` and the report, with the correction stated rather
      than quietly swapped. The honest reading is "the sets do not overlap", not an effect size.
- [ ] **`.git` is present in the agent's workspace, and the target repo is public on GitHub.**
      Cursor measured 14–21 points of score inflation from exactly this: agents retrieve the fix
      from history instead of deriving it, on 63% of successful resolutions they audited.
      Whether *our* tasks are reachable that way is unchecked — most are "add a KDoc", "rename a
      symbol", where the answer is not a past commit. But the read and debug tasks might be.
      **Do this before any further runs:** export without `.git`, restore for scoring.
      https://cursor.com/blog/reward-hacking-coding-benchmarks
- [ ] **Is the scoring path reachable by the agent?** If it can edit `build.gradle.kts`, add
      `@Ignore`, or touch a test source set, then `verify=test` is gameable. Score from a
      pristine checkout with the agent's diff applied to source files only.
- [ ] **Add a third outcome: infrastructure failure.** Tool-call parse error, timeout, server
      crash, context exhaustion. Reporting that rate separately is how "the model is weak" gets
      separated from "the harness is broken" — which has now cost us five separate investigations.
      mlx-lm has open issues (#607, #1096, #1125) producing exactly the shape of our quarantined
      run.
- [ ] **Analyse at task-run level, not run level.** 5 runs x 8 tasks = 40 Bernoulli trials.
      Collapsing to five run-scores throws away the task pairing, which is the dominant variance
      source. Publish the per-task 0–5 table as the primary result; it shows immediately whether
      a model fails task 7 every time (capability) or scattered tasks once each (noise).
- [ ] **Randomise run order.** Ours were sequential per model, so "model B is worse" is
      confounded with "the machine was 40 minutes hotter".
- [ ] **The denominator.** We publish a mean over 8 judged of 11 tasks. State that everywhere,
      including where the number is printed.
