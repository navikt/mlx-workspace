**Trap 4 is hit by every submission in the round.** Seven of seven print
`UV Index: undefined` and exit 0 on a payload without
`ultraviolet_index_clear_sky`. Not one model guarded it, and several wrote a test
that would have caught it had the test not run only against the live API, which
always supplies the field. A trap nobody avoids does not discriminate between
models, but it is the clearest finding here: absent data reads as data, in every
local model we have measured.

**Trap 5 is the only trap that separates the arms**, and at n=3 against n=4 that
is a difference of one run either way from being nothing.

## Reliability, which may matter more than the scores

Two of five qwen3.8 runs produced nothing: runs 07 and 09 each burned 85 minutes
and hit both the 900s plan cap and the 4200s implement cap. One of five qwen3.6
runs produced nothing: run 10 read the spec, replied "Let me find and read the
spec first", and exited 0 after eleven seconds and two turns.

At n=5 a 2/5 against 1/5 failure rate says almost nothing on its own. It is the
number to watch, because a dispatched task that returns nothing after 85 minutes
is worse for a developer than a wrong answer in ten.

## What this round cannot say

The arms are not configured alike. `MLX_OPENCODE_CONTEXT` is 131072 for
qwen3.8 and 65536 for qwen3.6, so qwen3.6 compacts mid-run and works from a
summary of the spec while qwen3.8 never approaches its threshold; `reasoning_effort`
is set on qwen3.8 only. This was accepted deliberately before the round on the
grounds that each profile is measured as it ships, which makes these absolute
readings per arm and not a comparison. Any sentence of the form "qwen3.8 beats
qwen3.6" is not supported by this round.

Three runs an arm meets the bar for scoring and not the five-run bar for
publishing.
