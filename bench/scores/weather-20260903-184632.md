## What the round actually shows

**Two of five submissions ship a CLI that cannot run, and both pass their tests.**
Run 04 calls `fetchWeather` at `src/index.js:41` and never imports it; the file
throws on invocation and 30 of 30 tests pass because no test loads `index.js`.
Run 03 has `bin/weather.js` requiring `src/main.js`, whose `run()` sits behind
`require.main === module`, false when loaded through `bin`; it prints nothing and
exits 0. Both models were told to ensure "the final cli works according to the
supplied specification".

That failure is worth more than the trap scores. Exit 0 with no output is the
shape trap 4 and trap 5 exist to catch, and the checklist misses it because every
trap is scored against a module rather than against the program.

**The checklist did not save the one model that named it.** Run 02 wrote
`// trap #2: boundary at exactly 75 uses >=` in `output.js:4`, implemented
`>= 75`, and pinned the wrong side with
`assert.strictEqual(getDescription(75), 'Overcast')`. The spec it was reading
says `> 75%`.

**Trap 8 was `n/a` in all five, and that is an instrument fault.** It is scored
from the transcript, and what the suite archives is the mise wrapper's summary
(`✓ exit 0 · 33 turns`), not the session. The real log exists at
`.bench-logs/<key>-<timestamp>.jsonl`, 228 events for a typical run, and each
archived wrapper log names its own jsonl, so the association is recoverable
without rerunning anything.
