# Benchmark coverage audit: gaps and duplicates, 2026-09-25

Desk audit. No GPU, no benchmark run, nothing in the live checkout touched. Sources are the
suites on `origin/main` (c33d15f), the night-1 results on the local branch
`bench/night-results-20260924-172038` (commit 5acb1de, not pushed), night 2's step log so far
(`.bench-logs/night2-20260924-234623/`), and two drafts that exist only as uncommitted files in
worktrees: `bench/decide-limits` (`~/mlx-ws-decide-limits`) and `design/quality-frontier`
(`~/mlx-ws-frontier`). Neither branch has a commit beyond 6306154. Per-class counts come from
`python3 .mise/tasks/bench-results --by-class`, run on main and once more with the night-1 files
copied in and then removed again.

## Summary

1. The main waste is data the bar never reads. Pure GPU redundancy in the night queues is under 15 min a night. `_by_class.py` reads only Ktor cheap-ops, `copilot-*`, `hybrid-*` and one debug file. It never reads `np-e2e` Copilot sessions (36 on night 1) or any frontend, Spring, Python or scale run.
2. **Harness-sha trap.** e5c34cd (19:54 on 24 Sept) edited `_profiles.py` for two keys that "the workspace server never reads". That changed `harness_sha` from 492141135fe6 to f62fbb8cbeae. `_by_class.py` keeps only the newest generation, so merging night 1 or night 2 drops all 16 runs at the old sha: 11 on main, 5 on the night-1 branch. That includes optiq's 12/12 read-qa and all the 8-bit evidence.
3. Top duplicates: the np-e2e E2E sessions against `bench-copilot` local rungs 1–3; `bench-system-one` inside `navpilot-e2e(-rerun)` d; decide-limits `lang-en` against the `_decide.py --eval` cases; the frontier's read-qa and multi-file rung 1 against R3 and M1; two competing cloud-arm plans.
4. **Structural gap.** The Copilot and delegate ladders have one task per class for read-qa (R2), edit-single (E1) and create-file (G2). The bar's `min_tasks = 2` can never be met there, so those verdicts cannot reach `trusted` at any n.
5. Cloud reference (`p_cloud`) exists for 6 task ids, all from Sonnet 4.6 in August. There is none for GPT-6 Sol (nav-pilot's current default orchestrator), and none for R3, D1, E3, D3 or debugging.
6. The local-only verdicts come from opencode talking to :8080 directly, a path no user runs. opencode through nav-pilot in local-only mode has never been measured. Copilot-local data has n = 3 per task (August, temp 0).
7. Unmeasured: Norwegian prompts, explanation and review, multi-turn sessions, quality past about 20k tokens of context, security-sensitive edits (E3 passes a model for logging a fødselsnummer), the redaction hook, the loop hook's false positives, and nav-pilot regressions as a recurring suite.
8. Recommendations, in order: fix the hash before merging night results; read np-e2e rows in `_by_class`; add a second task per class to the Copilot and hybrid ladders; run one cloud arm through `bench-frontier --cloud`, with GPT-6 Sol included; retire `bench-system-one`, `bench-decision` and `run-decision-bench`; key `task-classes.json` by target.

## 3. Duplicates

Ranked by what merging them buys: bar data first, GPU second.

1. **`bench-np-e2e` E2E sessions and `bench-copilot` local rungs 1–3.** Same path (Copilot CLI → nav-pilot → local), same tasks (R2, E1, M1 through `bc.run_sample("local", …)`, `.mise/tasks/_np_checks.py:439`), same repo. np-e2e runs 12 sessions per full profile (about 13 min, measured from `np-e2e-qwen3.8-27b-optiq-4bit-20260924-181038.json` phases), but writes them under an `e2e` key that `_by_class.py` never reads. Keep np-e2e as the runner, since it records the nav-pilot commit, footprint and guard signals. Retire running `bench-copilot` rungs 1–3 separately, and make `_by_class.py` read the np-e2e rows as condition `copilot nav-pilot=<commit> temp=<manifest>`. Also drop the "classifier on/off" split (`bench-np-e2e`, the `for state in on off` loop): the classifier is gone (decision.md item 6), so the two halves are one condition under two labels. Saves no GPU. It adds 36 Copilot-local samples from night 1 to the bar.
2. **`bench-system-one` ⊂ `bench-navpilot-e2e` d ⊂ `bench-navpilot-e2e-rerun` d; `bench-loop-hook` reuses the same fixture.** All three drive the `loop` and `poll` sessions from `_np_checks.SESSIONS`. system-one adds the LLM classifier probe, which was dropped after 0/7 (decision.md §3.5). The rerun is the version with the test-design faults fixed (nav-pilot-e2e.md, "Re-run of d and e"). Keep the rerun's d as the local-guard regression and `bench-loop-hook` for the cloud hook path. Retire `bench-system-one`, `np-e2e --system-one` and the classifier probe inside `_np_checks.probe` (0.2 min a run). Merge the two keepers into one guard-regression task with arms `local-guard` and `cloud-hook`, and give it the poll scenario: `bench-loop-hook` runs only the loop, so a hook that stops legitimate polls would pass it.
3. **decide-limits `lang-en` and `_decide.py --eval`.** `lang-en.jsonl` is "the two existing sets, in English" (`build.py`, `lang_sets()`), the same 32 cases as `bench/decide-cases`. `EVAL_SETS` even runs `--eval` on it as a cross-check. Keep decide-limits (per-case results, 9 sets, labels re-derived by `--check`). Once it lands, cut `_decide.py run` down to latency, logprob mass and cache eviction. A few GPU minutes.
4. **Frontier read-qa "callers" and multi-file rung 1 against cheap-ops R3 and M1/M2.** Same repo and ref (the frontier generates from `isoppfolgingstilfelle`), same path A, same question shapes: `rq-*` asks for the files that call a function, as R3 does; `fm-r1` threads an argument through 1–2 call sites. The frontier has the better verifier (answer-set, a reference solution that must build, allowed-files) and a difficulty axis. Keep both until the frontier has data, because cheap-ops is the only source of local-only bar data. After that, don't run both on the same profile in one night; fold R2, R3, E1 and M1 into the frontier as fixed anchor tasks, so a harness change can be compared across generations. Saves about 19 min per optiq profile-night (`night-2026-09-24.md`, steps 6–8).
5. **Two plans for one cloud reference arm.** design.md §5 item 1 extends `bench-copilot --arm cloud` to all 11 task ids. The frontier's `--cloud` runs opencode cloud-only through nav-pilot, the path `bench-hybrid`'s control arm uses. Both exist to fill `p_cloud`. Pick one: the frontier's, because its tasks are graded and verified and its path matches the control arm the delegate cost ratio is computed against. Run it with the current default orchestrator (GPT-6 Sol) as well as Sonnet 4.6.
6. **Scale S1–S4 and refactor A against the frontier's MMF ladder.** All three ask where a local mechanical edit stops working as the reference count grows. The frontier's rungs 4–6 (9–16, 17–40, 41+ sites) cover the same question on Ktor with reference solutions. Scale keeps one thing of its own, file spread against reference count on TypeScript (the S3 against S4 note in `targets/frontend-scale.json`). Retire refactor A as a strategy and keep scale as the only TS scale probe. Neither is in a queue, so no GPU is saved.
7. **Refactor B against the frontier's `decompose` variant.** Both ask whether per-file decomposition rescues a multi-file edit. B has the cloud decompose; the frontier has the harness decompose. Findings §3.3 already answered B for renames (it costs about as much as C). Keep the frontier variant and retire `bench-refactor`.
8. **`bench-decision` + `run-decision-bench` against `_decide.py`.** Both are logprob classification on the raw API. The first predates the product command, hard-codes :8080 and a profile, and writes no results file. Retire it.
9. **`cache-probe` against np-e2e warm TTFT.** Both measure prefix-cache reuse. np-e2e does it through nav-pilot's own server at 30k and 57k, the production path. cache-probe used the workspace server in August and found 99.3–99.5% for every model (BENCHMARKING.md). Keep cache-probe as a one-off check when a new model family is added, and don't queue it.
10. **Latency-only np-e2e steps.** Night 1 step 4 measured `c48k-ps512` latency (4 min), and night 2 step 1 runs the full suite on the same profile, latency included. A full run supersedes a latency-only run on the same profile. Don't queue both.

What stays because it only looks like a duplicate: cheap-ops R* against decide. R* is an agentic
session with tools; decide is one letter token over evidence it is handed. The frontier's Ktor
debug against frontend X1–X3: different codebases, and together they give DBG its second codebase.

## 4. Gaps

Ranked by how directly they block a local-vs-cloud decision.

1. **The harness hash orphans the evidence (the bar's integrity).** `bench-cheap-ops` hashes `_profiles.py` into `harness_sha` (`_harness_sha()`). e5c34cd added `MLX_NAV_PILOT_TEMPERATURE` and `MLX_NAV_PILOT_TOP_P` to `OPTIONAL_DEFAULTS`, which its own comment says the workspace server never reads. Every run after 19:54 on 24 Sept is f62fbb8cbeae, and `_cheap_ops_files()` keeps only the newest generation. Checked by copying the night-1 files in: every 492141135fe6 row disappears, including optiq read-qa 12/12 and all 8-bit data. Night 2's five optiq runs would then stand alone at 5 runs instead of pooling with the four from 23 Sept.
2. **`min_tasks = 2` cannot be reached on the Copilot and delegate ladders.** `bench-hybrid` RUNGS map one task per class: R2 (QA), E1 (E1F), M1/M2/D2 (MMF), G2 (NEW) (`.mise/tasks/bench-hybrid:99`). bench-copilot and np-e2e share them. So QA, E1F and NEW can never be `trusted` in local-only Copilot mode or in delegate mode, whatever n is. That is design.md §2.1 floor 1 against the ladder's shape.
3. **No cloud reference for most tasks, and none for the current orchestrator.** `p_cloud` is pooled from `copilot-*-cloud` and `hybrid-*-control`: R2, E1, M1, G2, M2 and D2, all Sonnet 4.6, 29–31 Aug. R3, D1, E3, D3, X1–X3 and every frontier task default to 1.0, and R1's fairness is unknown (design.md §1.2). nav-pilot's default orchestrator moved to GPT-6 Sol (mixed-mode research §3.1), and nothing has measured it. Night 2's hybrid step pins Sonnet 4.6.
4. **The local-only verdict is measured on a path users don't run.** cheap-ops is opencode straight to :8080: no guard, no policy, and the workspace server's sampling rather than the manifest's (mixed-mode research §3.1, "Not covered"). Users get Copilot → nav-pilot or opencode → nav-pilot. Copilot-local bar data is 3 samples per task at temp 0 from August. opencode local-only through nav-pilot has none.
5. **Statistical power below the floor.** No local-only cell meets the floor in the bar today (§2 matrix). Rows at 4 runs: optiq and 8-bit cheap-ops. Rows at 3 runs or fewer: 4-bit, every night-1 condition, debug (1 run), and every Copilot-local task. Silent classes need 32/32 to clear 0.95 (design.md §2.1). At 3 QA answers per cheap-ops run that is 11 clean runs, but read-qa also needs a cloud arm (gap 3) and must not lose runs to gap 1. Night 1's optiq t0 read-qa was already 8/9.
6. **Only Ktor reaches the bar.** The frontend, Spring and Python runs (1 each), scale (3) and Next.js (0) are named `results-<profile>-<suffix>.json`. `_cheap_ops_files()` needs a `-YYYYMMDD-HHMMSS-NN` stem, and these runs carry no `harness_sha`, so they are silently excluded. design.md §6 calls a verdict that generalises beyond one Ktor service the residual risk, and nothing in the queues addresses it. Python was 0/4 (`results-qwen3.6-35b-a3b-optiq-python.json`), the one untyped target.
7. **Security-sensitive edits are rewarded without checking.** E3 asks the model to log "the values of [the first public function's] parameters" in `OppfolgingstilfelleService.kt`. That function is `getOppfolgingstilfeller(personIdent: PersonIdentNumber)` (line 13–14 at the pinned ref b0351ed8). A pass is a fødselsnummer written to the application log, and `compile` accepts it. No task checks for a secret, PII, an auth change or an injection-safe edit. weather-cli's rubric had one trap of that kind (48gb-question.md).
8. **Explanation and review are unmeasured.** The only EXPL task, R1, is excluded (`task-classes.json`). The read-qa verdict rests on path/line lookups and caller lists. design.md sends "explanations, review text" to cloud with no data behind it, and Copilot local mode has no router, so its users will ask anyway (design.md §3b).
9. **"When not to delegate" is not scored.** `_by_class.py` counts only the samples that reached the worker (`delegated = [s for s in valid if s.get("local_calls")]`). A class the policy keeps on cloud is never checked for leakage: there is no false-delegation rate, and no cost of a bad dispatch. Night 2's rungs 1, 2, 4 and 5 hybrid ×6 will produce the data, but nothing reads it. Debugging has no rung at all (rung 7 undefined, `bench-hybrid:106`).
10. **Norwegian prompts.** Every task prompt is English (`bench/tasks.json`, `bench/targets/*.json`). `bench-language` varied the worker's instruction language, not the user's (findings §7.1). The only Norwegian user-style prompts are decide-limits `lang-no`, which is uncommitted and covers decide only. Nav developers write prompts in Norwegian, and the codebases have Norwegian identifiers throughout (`targets/README.md`).
11. **Long context, for quality.** No task drives an agent session past about 20k tokens. The 40k+ data is TTFT on a synthetic summarise prompt (`_np_checks.LATENCY_TARGETS`) and one prefill trace (nav-pilot-e2e.md, "8-bit past ~40k"). The 8-bit entry now ships at 48k, and the 4-bit at 64k, on latency and memory evidence alone.
12. **Multi-turn and follow-up sessions.** Only weather-cli (plan, then implement, 3 Sept) and the frontier's `retryK` variant (`--continue`, draft) use a second turn. Every bar sample is a fresh one-shot session.
13. **Hooks and nav-pilot regressions have no recurring suite.** The redaction hook (#940) has no end-to-end test here. The loop hook has one pending loop-only session. `min_nav_pilot` (an old client should hide a gated entry, `model-manifest` `MIN_NAV_PILOT`), the cached-source fallback for network blips (pending-tasks.md §8), and the dead-thread exit (the rerun's e, once, which also found exit status 0 on the failed launch) each ran once or never. night-preflight checks that the binary contains a commit, not that the feature works.
14. **Nothing from real repos or sessions.** All targets are real navikt repos at pinned refs, which is good. The runtime feedback that would show whether the classes hold in real sessions (design.md §3c) is not built.
15. **Create-file and debug get no new tasks.** The frontier covers QA, E1F, MMF and DBG (`_frontier.BINS`, `DEBUG_BREAKS`) but not NEW. design.md §5 item 3 asked for two more create-file tasks. NEW stays at 2 tasks on one codebase.
