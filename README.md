# mlx-workspace

Run LLMs locally on Apple Silicon with [MLX](https://github.com/ml-explore/mlx), and point AI
coding tools at your local server. No cloud calls.

## How it fits together

MLX loads model weights (say `mlx-community/Qwen3-Coder-30B-A3B-4bit`) into RAM, `mlx_lm.server`
exposes them over HTTP on `:8080`, and any OpenAI-compatible client talks to that.

| Component | Role |
|---|---|
| Model | The LLM weights, which set capability and RAM usage |
| MLX / mlx-lm | Runs the model on the unified CPU/GPU/ANE of Apple Silicon |
| mlx_lm.server | Bridges the model to the OpenAI API format |
| mlx_lm.chat | Chat with the model, no server needed |
| aider | AI assistant that edits files, runs tests, and commits |
| opencode | AI coding agent with TUI, configured via `opencode.json` |
| Copilot CLI | GitHub Copilot routed to the local server instead of the cloud |

Model measurements and verdicts are in [MODELS.md](MODELS.md), how the measuring is done in
[BENCHMARKING.md](BENCHMARKING.md), and the written conclusions in [reports/](reports/README.md).

## Prerequisites

- Apple Silicon Mac (M1–M5). Tested on a 32 GB M1 Max and a 128 GB M5 Max, see [MODELS.md](MODELS.md)
- [mise](https://mise.jdx.dev) (`brew install mise`)
- [rtk](https://github.com/rtk-ai/rtk) (`brew install rtk-ai/tap/rtk`), compresses command output before it reaches the model
- Python 3.12 for aider (`brew install python@3.12`)
- `gh` CLI for the Copilot task (`brew install gh`)

## Setup

Installs `mlx` and `mlx-lm` into a local `.venv`, and `aider-chat` via pipx.

```bash
mise run setup
```

rtk compresses shell output by 60–90% before it enters the model's context window. One-time, per
machine, opencode picks it up as a plugin:

```bash
# 1. Install the opencode plugin
rtk init -g --opencode

# 2. Register it in your global opencode config (~/.config/opencode/opencode.json)
#    Add this line to the JSON:
#    "plugin": ["~/.config/opencode/plugins/rtk.ts"]
```

Step 2 is manual: opencode does not auto-discover plugins from `~/.config/opencode/plugins/`.
The local `opencode.json` generated by `mise run opencode` already lists it as a fallback.

## Usage

```bash
mise run server
```

Serves an OpenAI-compatible API at `http://localhost:8080/v1`. Then, in a second terminal:

```bash
mise run aider      # aider pair programmer
mise run opencode   # opencode AI coding agent
mise run copilot    # GitHub Copilot CLI
```

```bash
mise run chat   # interactive chat with the model (no server needed)
mise run run    # single prompt, prints and exits
```

```bash
mise run models-list                                               # show downloaded models and sizes
mise run models-clean                                             # interactive picker to delete a model
mise run models-clean mlx-community/Qwen2.5-Coder-32B-Instruct-4bit  # delete by name directly
```

## Configuration

Switch models with `mise run model-use <profile>`. It reads `profiles/<profile>.toml` and writes
`MLX_MODEL` plus that model's sampling parameters into `mise.local.toml`, which overrides the
default in `mise.toml`. Edit `mise.toml` directly only to change the fallback.

Every mise task reads `MLX_MODEL`. `server`, `chat` and `run` pass it straight to mlx-lm. `aider`
and `opencode` regenerate `.aider.conf.yml` and `opencode.json` from it on each launch (via
`aider-init` and `opencode-init`), so you never edit those files by hand. `copilot` passes it via
env vars. Model options and notes in [MODELS.md](MODELS.md).

## opencode context compaction

opencode compacts a session by feeding the full history back to the model for summarization, then
replacing it with the summary. That is ~5s on a cloud model and 2–3 minutes on a local 9B.

Auto-compaction only fires when `model.limit.context` is non-zero. Models served by `mlx_lm.server`
are not in opencode's registry, so their limit is `0`, and history piles up past 50k tokens until
you run `/compact` by hand. `opencode-init` declares a limit in the generated `opencode.json`:

```json
"models": {
  "mlx-community/Qwen3.5-9B-MLX-4bit": {
    "limit": { "context": 24000, "output": 8192 }
  }
}
```

opencode's math is `usable = context - output_reserve = 24000 - 8192 ≈ 15800 tokens`, so compaction
fires at ~16k, small enough to summarize in ~30s. The model itself supports 32k; the lower declared
limit is intentional, since less context at compaction time means faster local inference.
Per-profile values live in [MODELS.md](MODELS.md#opencode-declared-context-limits).

| Situation | What to do |
|---|---|
| Session just started | Compaction is cheap, keep going |
| Approaching 30k tokens | Start a new session with `/new` to skip compaction entirely |
| Compaction triggered | Wait it out (~30s). Don't cancel, a truncated history may confuse the model |
| Server OOM during compaction | See the OOM note below; reduce `MLX_CACHE_SIZE` |

## Unlocking more VRAM (Apple Silicon)

CPU and GPU share one pool of RAM, and macOS caps the GPU at ~70–75% of it to keep the OS stable,
leaving ~22–24GB for models on a 32GB Mac. Override the cap at runtime, no reboot needed:

```bash
mise run vram-status        # check current limit
mise run vram-set           # set to 26GB (recommended default for 32GB Macs)
mise run vram-set 28        # set a custom GB value
mise run vram-reset         # restore macOS default
```

Profiles carry their own ceiling as `gpu_wired_limit_gb`; `mise run model-use` applies it.

| 32GB Mac | OS headroom | Command |
|---|---|---|
| 24 GB | 8 GB (safe default) | `mise run vram-set 24` |
| 26 GB | 6 GB (recommended) | `mise run vram-set 26` |
| 28 GB | 4 GB (risky) | `mise run vram-set 28` |

| 128GB Mac | OS headroom | Used by |
|---|---|---|
| 96 GB | 32 GB | `qwen3.8-27b-8bit` (~28 GB model, room to spare) |
| 115 GB | 13 GB | `deepseek-v4-flash-3bit` (~84 GB wired) |

> Allocating too much causes hard lockups, beachballs, or forced reboots. Leave at least 4–6 GB for
> macOS. The setting resets on reboot.

> If the server crashes during inference with `Insufficient Memory` or
> `kIOGPUCommandBufferCallbackErrorOutOfMemory`: the KV cache is not the only GPU memory consumer.
> At 50k+ token contexts the forward pass itself needs 4–6 GB for intermediate activations and Metal
> command buffers, on top of the cached KV state. Budget
> `GPU cap = model weights + KV cache held + ~6GB activation buffer`, so `26 GB = ~6 GB + 14 GB + 6 GB`.
> Reduce `MLX_CACHE_SIZE` to limit how many sessions accumulate, and lower `vram-set` if that is not
> enough. Each cached session at ~80k tokens holds ~3 GB, so 6 sessions × 3 GB = 18 GB can exceed a
> "safe" cap with no warning. `MLX_CACHE_BYTES` will not help: mlx-lm builds its prompt cache
> without a byte limit, so the setting is a no-op and slots are the only bound.

> On macOS Ventura and older, the sysctl key is `debug.iogpu.wired_limit` and takes bytes instead of
> MB. The mise tasks use the Sonoma+ key (`iogpu.wired_limit_mb`).
